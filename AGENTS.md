# Daymark agent rules

Project-specific conventions for anyone (human or agent) working in this
repository. The block above is generated by `next dev` and must be preserved
verbatim; everything below it is Daymark-owned.

## Hard rules

1. **Documentation-only changes stay documentation-only.** Never mix source,
   migration, dependency, or deployment changes into a docs reorganization —
   see [plans/IMPLEMENTATION_PLAN.md](plans/IMPLEMENTATION_PLAN.md).
2. **Do not commit or push** unless the owner explicitly asks.
3. **Never read or print secret values.** Refer to variable _names_ only
   (`.env.example`, [docs/operations/ENVIRONMENT.md](docs/operations/ENVIRONMENT.md)).
4. **Preserve the generated block above** (`<!-- BEGIN/END:nextjs-agent-rules -->`)
   byte-for-byte when editing this file.
5. **Migrations are the source of truth** for the database
   ([docs/architecture/DATABASE.md](docs/architecture/DATABASE.md)); schema
   changes are migration-only, additive where possible, and must update
   DATABASE.md in the same change.
6. **RLS:** any new user-owned table must be added to the ownership list in
   the migration _before_ it is exposed — the `profiles` table was missed and
   became a verified security gap ([docs/product/BACKLOG.md](docs/product/BACKLOG.md) S1).

## Documentation rules

- Start from [docs/INDEX.md](docs/INDEX.md): **one source of truth per
  subject** — update the owning document, don't duplicate.
- Every factual claim about the code must be linked to source
  (`file:line`) or marked as a recommendation.
- Use the status vocabulary: Implemented · Partially implemented · Broken ·
  Configuration required · Not verified · Planned · Deprecated.
- Integration statuses change only with dated evidence; a configured
  credential is not a working integration.
- After a change that invalidates a documented claim, update that document in
  the same change.

## Verification gate

Before presenting work as complete:

```bash
npm run lint && npm run typecheck && npm test && npm run build
```

Schema changes additionally re-run
[`supabase/tests/rls_isolation.sql`](supabase/tests/rls_isolation.sql) on a
disposable Supabase project. Known gaps in current coverage:
[docs/development/TESTING.md](docs/development/TESTING.md).
